# Batch 3 — 拍摄日期可信化、离线索引与真实全库测量

日期：2026-10-31  
范围：M1 离线索引 / 启动首屏 / 网格滚动与 M3 日期来源、真实 Lexar 库测量。  
约束：媒体文件只读；不引入第三方依赖；保持 `swift build` 与测试通过。

## 1. 实现

### 1.1 `MediaDateParser`

新增 `Sources/MediaViewer/Services/MediaDateParser.swift`，只解析**文件名**，不读文件：

- `IMG_20240702_162635` / `IMG-...` / `PXL_...`
- `Screenshot_2025-09-03-091713` / `Screenshot-...`
- `Screenshot 2024-01-02 at 10.11.12`
- `扫描文件_20240728_192105(...)`
- `微信图片_20240702162635.jpg`
- `mmexport1723456789012.jpg`（10 位或 13 位 epoch）
- `image_editor_20240702...`、纯 `20240702_162635`（必须同时有日期和时间）
- 带扩展名、空格、括号、中文及 trailing suffix 的文件名
- 非法日期（20241340）、13 位非法月份、epoch < 1990-01-01 或 are > 明天 → nil；未来时间不属于可信拍摄时间

实现入口：`MediaDateParser.parse(fileName:) -> Date?`。日期按当前时区构造 `DateComponents`，只用于展示和排序。

### 1.2 `MediaDateSource`

新增枚举：

```swift
enum MediaDateSource: String {
    case exif
    case quickTime
    case filename
    case fsModified
    case fsCreated
}
```

显示文案：EXIF / QuickTime / 文件名 / 文件修改时间 / 文件创建时间；nil 显示“时间来源未知”。

### 1.3 提取顺序

`MetadataExtractor` 按以下顺序选择第一个有效日期：

1. EXIF `DateTimeOriginal`，缺失时 `DateTimeDigitized`
2. QuickTime `creationDate()`（视频）
3. 文件名模式（`MediaDateParser`）
4. 文件修改时间（仅当早于文件创建时间，避免复制/恢复把 mtime 刷新为今天）
5. 文件创建时间
6. 都无效 → `derivedDate = nil`

示例：`IMG_20240702_162635` 即使 mtime/ctime 是 2026，也使用 2024-07-02；`mmexport1723456789012` 以 epoch 解析。

### 1.4 持久化

`MediaItemEntity` 新增：

- `derivedDate: Date?`
- `dateSourceRaw: String?`

旧 `creationDate` 继续写入，作为兼容列。`MediaItem` 的 `creationDate` 现在是 `derivedDate ?? creationDate` 的兼容读取，新增 `dateSource`。扫描后所有行的 `derivedDate`/`dateSourceRaw` 都有值；没有任何可信日期的行写入 sentinel `"unknown"`，避免每次启动重复提取。旧库（两列为 NULL）会触发一次全量 metadata 重扫。

### 1.5 增量发布与首屏

`MediaScanner` 每提取 256 个文件就保存并回调 `indexed`。`LibraryViewModel.mergeIndexedItems` 在扫描期间把已更新的日期刷新到内存/网格，而不是等整库扫描完。

`LibraryViewModel.performScan` 现在**先读取已有索引并发布首屏**，再启动扫描；扫描结束再 `fetchItems` 校准。这样即使全库扫描需要 2 分多钟，已有库的首屏也不再等待扫描完成。

### 1.6 全屏查看器

`FullscreenViewerView` 信息面板显示当前照片/视频的拍摄日期和来源：

`2024年7月2日 16:26 · EXIF` / `· 文件名` / `· 文件修改时间` / `时间来源未知`

### 1.7 媒体扩展

`MediaScanner.isMediaFile` 和 `MetadataExtractor`/`ThumbnailGenerator` 统一支持：

`.jpg .jpeg .png .gif .webp .mp4 .mov`

缓存目录 `.mediaviewer` 和 `.database` 继续跳过，不把应用自己生成的缩略图当媒体。

### 1.8 未知时间分组

`TimeFocus` 新增“未知时间”焦点，`TimeGrouping` 将 `derivedDate == nil` 的项放到“未知时间”分组；不再丢弃无日期项。设置面板显示“已设置日期：Unknown Date”。

### 3.4 扫描与首屏

| 指标 | 数值 | 口径 |

## 5. 已知限制

- 任务书的 48,922 包含 `.mediaviewer` 缓存缩略图；应用按设计跳过缓存目录，索引源媒体 40,661 行。

- `derivedDate` 的时区使用当前系统时区；跨时区迁移可能造成小时级差异。
- 冷启动且**没有旧索引**时，首屏仍需等枚举和第一批 metadata；本次验收是已有用户库路径。
