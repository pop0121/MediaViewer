### 判定

四项排查：

1. **迁移/重建路径只扫部分目录**：排除。旧 root `.mediaviewer` store 40119、当前新 store 40119，均与磁盘一致；旧文件未删除。
2. **磁盘枚举遗漏**（递归/隐藏/符号链接/子目录）：磁盘用同口径枚举 40119，媒体扩展名与 `.mediaviewer/.database` 跳过一致；不是枚举遗漏。
3. **UI 过滤状态卡住**：`regionFilter`、`timeFocus`、`clusterSelection` 均无 UserDefaults 持久化（代码仅在内存中）；默认路径没有过滤。不是过滤残留。
4. **scan 中途出错未补跑**：近三天日志没有 scan 失败；新 store 计数与磁盘一致。

**直接根因**：首屏只加载 `batchSize=1000`，按 `creationDate` 降序；该库最新 1000 条全部是 2026 年，首屏之后只有用户滚到网格最底部附近才触发下一页。用户视觉上“库只剩 2026 年”。两个当前 store 都是完整的，UI 分页是唯一根因。

### 修复

- `LibraryViewModel` 首屏出现后启动一次后台时间线补全：分页加载至 `items.count == totalItemCount`；快速滚动期间暂停/重试，不挤压当前手势。
- `loadMoreItems` 只在实际 fetch 成功后推进 offset，避免失败页吞页。
- 修复验收（instrumented appcopy + 真实 store）：
  - 首屏 `items=1000 total=40119`；
  - 后台补全过程中 `MV_TICK`：t=2s 12000（随后用户滚动，补全让出）/ t=14s 18000 / t=20s **40119**；
  - 完整时间线滚动基准：docH 约 1.4M，12s、711 ticks，>25ms 2 次、>50ms 2 次、>100ms 1 次，max 110.8ms（补全期间；补全结束后不再增长）。
  - `MV_PROBE docH=356982 items=12000`（滚动期间），补全后 items 40119。

旧 `.mediaviewer/Store` 保留未动；用户媒体文件未写入。

## M2：视频连播

### 复现（修复前）

真实 `VideoPlayerView` + `NSHostingView`，`.id(item.id)` 每个视频重建 `AVPlayerView`；v01 播到 ended 后切 v02。开启 enhancement（custom `videoComposition`）时：

- 第一次崩溃：`AVPlayerItem dealloc` → `AVPlayerItemTrack dealloc` → `AVURLAsset dealloc` → `AVAssetDownloadCache dealloc` → `CFRelease`（`Video12-2026-11-01-162725.ips`）。
- 另一次：`makeNSView -> player.play()` 内部 `AVPlayerController` KVO / `AVPlayerView dealloc` 崩溃。
- 修复前关闭 enhancement 时，因 `.id` 仍重建视图但无 composition，样本可播完；用户环境中的 enhancement 状态触发更严重路径。

### 修复

1. `FullscreenViewerView` 对视频使用稳定 id（所有视频共享 `video-player`），不再每条视频新建 `AVPlayerView`；照片仍按 item id 重建。
2. `VideoPlayerView`：
   - `makeNSView` 不再同步 `play()`，统一在 `updateNSView` 播放，避开 AVPlayerController KVO 建立竞态。
   - 切换前 `prepareForReplacement()`：暂停并清空旧 item 的 `videoComposition`，再替换 item。
   - `dismantleNSView`：清空 `AVPlayerView.player` 和 coordinator 的强引用；不在 dismantle 中做 nil item 替换。
