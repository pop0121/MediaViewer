# MediaViewer 批次9交付报告（2026-11-01）— 网格滚动主线程重构

## 结论（先行）

**已完成网格滚动重构，60 Hz 轮询下 12 秒快速滚动的 >25 ms 停顿从 53–64 次降到 7–9 次，最大间隔 33.6–47.5 ms；首屏 1000 条索引到网格约 0.35 s。**

- 原有问题不只是 `LazyVGrid`：迁移到 `NSCollectionView` 后，cell 创建、可见单元更新和每次 `layoutSubtreeIfNeeded` 仍会造成主线程尖峰；即使全部 320 px 缩略图已在内存，12 秒滚动仍有 53 次 >25 ms 停顿。
- 最终方案改为 **单 `NSView` + CALayer 虚拟画布**：文档只有一个视图，可见图块使用固定图层池；滚动只维护可见集合，不再创建/回收 `NSCollectionViewItem`，也不再触发布局引擎。
- 修正了两个实测中发现的正确性问题：
  1. 缩略图目录原先每次 `thumbnailURL` 都调用 `FileManager.createDirectory`；已改为纯路径计算，文件生成时才创建目录。
  2. 长分组只按“分组头是否与可视区相交”选中；滚到长分组内部时整屏空白。已改为按 `Section` 的完整高度相交，并只扫描可见行范围。
- 缩略图加载增加全局 `AsyncSemaphore(limit: 3)`，避免 ImageIO 并发解码抢走主线程；这是滚动指标从 19–21 次降到 7–9 次的关键。

## 3. 改动

### 3.1 `Sources/MediaViewer/Views/GridCollectionView.swift`（新文件）

- `GridCanvasLayout`：在给定宽度下一次性计算每组的 header、每个图块 frame 和总高度；折叠组只保留 header 高度；几何完全不依赖缩略图是否加载，因此加载/失败不会改变文档高度。
- `GridCanvasView`：
  - `isFlipped = true`，document 的 `CALayer` 使用 `isGeometryFlipped = true`，与 AppKit 顶部坐标一致。
  - 可见集合按“组完整高度”相交、再按行范围 `firstRow...lastRow` 只遍历可见行；长分组（例如 559 条）不会每秒扫描全部条目。
  - 图块是 `GridTileLayer`，用 `CGImageLRU` 同步命中直接设置 `contents`；未命中才启动一个后台 Task。
  - 图块图层池：滚出时隐藏并回收，滚入时复用；不再销毁/重建 CALayer，避免 `_display` 和 `prepare_contents` 的尖峰。
  - 图像只对**新进入可见集合**的 key 计算 `ThumbnailInput`、查缓存和启动加载；已经在屏上的图块只更新 frame。
  - 鼠标点击按几何命中图块并调用 `onOpen`；视频图块绘制播放角标。
- `GridContainerView`：
  - 保留 `NSScrollView` 的自然滚动手感、滚动条和弹性；
  - 吸顶 header 是独立的 `GridPinnedHeaderView`，不参与 collection 布局；只在该组变化时更新文字/折叠状态；
  - 速度检测仍以 900 pt/s 阈值设置 `isFastScrolling`，静默 120 ms 复位；
  - 分组变更时保存/恢复 `GridScrollAnchor`，避免折叠或翻页时跳位；
  - 接近底部时触发 `onLoadMore`；快速滑动期间由 ViewModel 拒绝，停稳后 `setFast(false)` 再补一次，解决“快速滑到底后不再加载”的边界。
- 删除旧 `MediaCellView.swift`、`ScrollActivityObserver.swift`、`SectionFrameReader.swift`：SwiftUI 网格路径已完全退出，保留会形成第二套布局约定。

### 3.2 `Sources/MediaViewer/Views/GalleryView.swift`

- 网格改由 `GridCollectionView` 承载；保留全屏查看、分组选择、地图模式、时间面包屑和 `onVisibleSection`。
- 恢复分页：`onLoadMore` 调用 `viewModel.loadMoreItems()`，不再依赖 `LazyVGrid` 末尾的 `ProgressView` `.task`。

### 3.3 `Sources/MediaViewer/Services/ThumbnailGenerator.swift`

- 网格缓存从 `NSCache<NSString, NSImage>` 改为 `CGImageLRU`（320 px 层 1 GB；640 px 层 512 MB；全屏层 512 MB，可用环境变量覆盖）。
- `thumbnailURL` 缓存 `root|relativePath|mtime|tier` 到 URL；`stableHash` 缓存 SHA-256，避免每个可见图块重复哈希。
- 增加同步 `cachedImage(for:tier:rootURL:)`，画布命中热缓存时不再为每个图块创建 Task。
- 增加 `AsyncSemaphore(limit: 3)` 包住 `loadOrGenerate`：磁盘读取和 ImageIO 解码不再无界并发；避免后台解码与主线程争抢。
- `saveThumbnail` 生成时才创建缩略图目录；`PersistenceController.thumbnailsDirectory` 变为纯路径函数（原先每个 cell 都做一次 `createDirectory`）。
- `ThumbnailImage` 改为持有 `CGImage`，`NSImage` 只在实际视图需要时创建。

### 3.4 验证中发现的正确性 bug

- **整屏空白**：初版 `sectionRange` 只取“header 与可视区相交”的组；滚入长组内部（例如 `n=559`，header 已在屏幕上方）时返回空集合。截图 `MV_SNAPSHOT_Y=4000` 复现。改为完整 `Section` 高度相交后，同一位置显示 10 列图块；延迟 5 s 截图确认缩略图已填充。
- **滚动位置被重置**：初版每次 `updateNSView` 都写 `documentView`/重新布局；`scrollTarget` 也没做 token 去重，导致 y 在 0/320 之间反复。增加 token 去重和 `lastMinimumItemWidth` 后，边界滚动稳定到 `y=7766`。

## 5. 风险与后续

1. **loadGate=3 的代价**：快速滚动时新进入屏幕的图块可能短暂显示占位色；这是用一点点可见延迟换主线程稳定。若用户更重视“立即看到图”，可把 limit 调到 4–6，但本机 >25 ms 停顿会回到 14–19 次。
2. **画布没有 NSCollectionView 的辅助功能/拖拽/选择语义**：当前只有点击打开和吸顶 header；如后续需要多选、拖拽导出，需要补 `NSAccessibility` 与鼠标框选。
3. **1 GB LRU 是硬上限**：本样本 1000 张 320 px 图全部驻留；3000+ 张时按 LRU 淘汰，滚动回看会重新读盘。应在 3007 库上再测冷/热两轮。
4. **分页只在滚动近底部触发**：`loadMoreItems` 仍受 `isFastScrolling` 拒绝；停稳补页只覆盖“已到底”场景。若需要在搜索/筛选后立即填满视口，应由 ViewModel 主动预取下一页。
5. **测试探针未入库**：`ScrollProbe` 只存在于 `/private/tmp/mvbench/appcopy`；仓库没有基准 target，后续需要可重复基准时应建立独立性能 harness。

## 7. 批次9收尾复测（2026-11-01 14:20）

收尾在批次9画布上又做了三处低风险改动，解决“快速滑动时仍创建解码任务”和“分页把首屏 fetch 放回主线程”的问题：

1. **快速滑动期间跳过缩略图磁盘读取/解码**：`GridCanvasView.setFastScrolling(true)` 取消在途 tile task；新进入视口的图块只做同步内存缓存命中，未命中先留空。滑动停止后 `updateVisible(force:)` 再补图。滚动手感优先，静止后完整填充。
2. **分页 fetch 移到私有队列**：`fetchItems` / `fetchBatchItems` 不再使用 `viewContext`，在 `newBackgroundContext().perform` 中完成 Core Data 取数并转成 `MediaItem`；首屏和后续页都不再占用主线程做 1,000 行映射。
3. **分页等待快速滑动结束**：`loadMoreItems` 恢复 `!isFastScrolling` 门控。画布在 `setFast(false)` 时重新 arm 并补一次；避免 fling 中途 append 1,000 条触发整个画布重建。
4. **预取窗口**：正常浏览 ±48；快速滑动停止后先用 ±24（约两屏）补齐，下一次静止的 `prefetchThumbnails` 再扩到 ±48。
