## 1. 数据源调查（11-04，办公 Mac 实测）

| 数据源 | 路径 | 状态 |
|---|---|---|
| `TransferRecord.db`（传输记录） | `~/Library/Application Support/pcsuite/database/` | 849 条记录；`phonePath`（手机端完整路径，父目录=相册名）+ `savePath`（Mac 落点）成对保留；其中 `VIDEO_SET` 778 条、`phonePath` 非空 846 条、文件名冲突仅 2 个 |
| `AlbumSync.db`（vivo 账号相册同步） | 同上 | 空表（用户未开启云相册同步），仅有表结构 |
| `.albumBackup`（备份元数据） | `~/Documents/vivo办公套件/备份/*/​.database/` | SQLite 空库（0 行），仅表结构 |
| `RecordSync.db` → `Photo` 表 | 同 pcsuite database 目录 | 空 |

关键判定：

- vivo 自建相册在手机上由目录支撑（bucket 机制），故 `phonePath` 的父目录即相册名。
- pcsuite 无公开 API，app 只能**只读其本地 SQLite 缓存**，不能主动连手机。
- 用户反馈"视频被平铺到一个视频目录"的那次导出在 `TransferRecord.db` 中**无任何记录**（全部 849 条 `savePath` 均无该目录）——**已丢失的相册归属无法从本机缓存恢复**。要留下记录，今后需经 pcsuite 拖拽/导出有结构的目录。

## 2. 实现

### 2.1 数据模型（零关系迁移风险）

- `MediaItemEntity` 仅新增 1 个可选 String 列 `albumNamesRaw`（JSON 编码的 `[String]`），轻量迁移 100% 安全；未建 Core Data 关系。
- **目录相册不落库**：`MediaItem.folderAlbumName(relativePath:)` 由相对路径父目录即时推导（根目录直属文件无目录相册）。
- **vivo 导入相册入库**：`VivoAlbumImporter` 拥有 `albumNamesRaw` 整列，每次导入全量重算、幂等（测试曾抓到"空记录不清除旧名"的真 bug，已修）。
- `MediaItem.albumNames` = 目录相册（在前）+ 导入相册（去重、字典序），排序稳定。

### 2.2 VivoAlbumImporter

- 只读打开 `TransferRecord.db`：SQLite3 C API + `immutable=1` URI；路径经 `URLComponents` 百分号编码（实测路径含空格 `Application Support` 可正常打开）。
- 仅取 `phonePath` 与 `savePath` 均非空的行（文件夹级聚合行 `IMAGE_SET`/`VIDEO_SET` 的 `phonePath` 为空，无相册信息，跳过）。
- 相册名 = `phonePath` 父目录最后一段；同一 `savePath` 多条记录取并集。
- 匹配：`savePath` 标准化后 vs `rootURL + relativePath` 字符串拼接（与扫描器同口径）；标准化兜底双斜杠差异。
- 触发：每次扫描后维护阶段自动执行 + 侧栏按钮手动重导；SQLite 查询 849 行量级，成本可忽略。
- 沙盒：打包 `.app` 无权限读其他应用数据时返回 `accessDenied`，侧栏出现"授权访问…"按钮，经 `NSOpenPanel` 选择 `TransferRecord.db` 并持久化安全作用域书签（UserDefaults key `pcsuiteDatabaseBookmark`）。

### 2.3 UI

- `GalleryView` 改 `NavigationSplitView`：侧栏 `AlbumSidebarView`（列宽 150–320pt，理想 200pt）。
- 侧栏："所有媒体"（总数徽标）+ 相册列表（计数徽标，按数量降序、同名字典序）；无相册时显示占位提示。
- `LibraryViewModel.selectedAlbum` 为筛选状态，与 `groupingMode`（日期/地点）正交：选中相册后内部仍按当前分组模式分桶；对地图模式同样生效。
- 相册计数基于已加载分页（首批 1,000 行），扫描后后台时间线水合自动补全。
- 导入结果/未找到/拒绝访问等状态在侧栏底部以一行提示展示。

- **已平铺导出的视频无法恢复相册归属**（无记录）；今后需经 pcsuite 按相册传输/导出，或直接按相册归置到命名文件夹（目录相册自动生效，覆盖更全，为零依赖推荐路径）。
- vivo 缓存导入只覆盖经 pcsuite 传输过的文件；`AlbumSync.db`（云相册同步）当前为空，若未来开启可作为更全的数据源（表结构已探明：`AlbumFolder.folderName` + `AlbumFront.folderId`）。
- 相册计数随分页水合增长，非最终值（扫描完成后后台水合收敛）。
- 打包 `.app`（沙盒）需用户经侧栏授权选择一次 `TransferRecord.db`；`swift run` 无沙盒直接可读。
