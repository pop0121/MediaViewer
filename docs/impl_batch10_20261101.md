# MediaViewer 批次10交付报告（2026-11-01）— exFAT Scan failed 修复与索引迁移

## 结论（先行）

**根因是 Core Data 的 SQLite store 不能开在 exFAT（`MNT_UNKNOWNPERMISSIONS`）卷上，不是媒体文件权限。** 批次10 已把 Store/Thumbnails 迁到 Application Support 下的 root-hash 目录：

- macmini 真实 Lexar exFAT 卷：`outcome=migrated`，**无 Core Data error**，`First screen items=1000 total=40119`，`Scan complete processed=0 total=40119`。
- 扫描期间 Lexar 根下**没有新增文件**；旧 `.mediaviewer` 8291 个文件的 sha256 清单前后完全一致。
- 办公 Mac APFS 迁移后：首屏 **0.30–0.33 s**；12 s 滚动 **10 / 4 / 9 次 >25 ms**，>50 ms **0**，max **45.1 ms**；RSS **96.8 / 92.9 MB**。
- 迁移单测 3/3 通过：有效旧 Store 复制试开、损坏旧 Store 重建、root-hash 稳定性。
- `swift build -c release` 双机通过；`swift test` 通过。

## 1. 根因与复现证据

任务书给出的 macmini 复现：

```text
CoreData addPersistentStoreWithType 返回 NSCocoaErrorDomain(256)
filesystem = exfat
MNT_UNKNOWNPERMISSIONS
File Device ID 0 vs Device ID 16777228
旧 Store: /Volumes/Lexar/vivo X100s Pro+732bfe/.mediaviewer/Store/MediaViewer.sqlite
```

**为什么是 Core Data，而不是普通文件权限**：

- exFAT 的 noowners/未知权限模型下，SQLite 无法在该卷完成 POSIX 权限假设，`addPersistentStore` 在打开阶段失败。
- 同一批媒体文件可被枚举；错误发生在 store 打开，而不是 ImageIO/AVFoundation。
- 旧实现把 store 放在 `<root>/.mediaviewer/Store/MediaViewer.sqlite`，因此每个 exFAT 根都会命中。
- 0.9 的错误只显示 `Scan failed: ... permission`，丢失了 `NSCocoaErrorDomain 256` 与实际 store 路径，导致误判为媒体文件权限。

## 2. 新布局

路径由 `MediaStorageLocations` 统一生成：

```text
<Application Support>/MediaViewer/<sha256(root 标准化路径) 前16位>/
├── Store/
│   └── MediaViewer.sqlite
└── Thumbnails/
    └── <relativePath|mtime 的 sha256>-<tier>.jpg
```

- **未沙盒**：`~/Library/Application Support/MediaViewer/<hash>`。
- **沙盒**：系统返回 `~/Library/Containers/com.example.MediaViewer/Data/Library/Application Support/MediaViewer/<hash>`；这是沙盒兼容的 Application Support，不会回到媒体卷。
- macmini Lexar 实测 hash：`25b507cccdfe3027`（root `/Volumes/Lexar/vivo X100s Pro+732bfe`）。
- 媒体根只读；不再创建根下 `.mediaviewer` 新文件。

## 3. 一次性迁移与回退

`PersistenceController.openForRoot(_:)` 的顺序：

1. 创建 Application Support 下的 `Store` 与 `Thumbnails`。
2. **新 Store 已存在** → 直接打开，返回 `.existing`（不重复迁移）。
3. 不存在且旧 `<root>/.mediaviewer/Store/MediaViewer.sqlite` 存在：
   - 复制 `MediaViewer.sqlite`、`-wal`、`-shm` 到新目录；
   - 试开复制后的 store；
   - 成功：返回 `.migrated`。
4. 复制失败或复制后的 store 打不开：
   - 只删除**新目录半成品**；
   - 新建空 store，返回 `.rebuiltAfterFailure`，随后全量扫描重建索引；
   - **旧 `.mediaviewer` 不删除、不清空、不改写**。
5. 没有旧 Store：新建空 store，返回 `.fresh`。

旧 Thumbnails 策略：

- 旧 `.mediaviewer` 原样保留，成为孤儿目录，等用户决定清理。
- **APFS**：按需惰性复制单个旧缩略图到新 `Thumbnails`，避免启动时复制 300 MB。
- **exFAT**：不搬旧缩略图；新路径按需从媒体文件重新生成（符合“exFAT 上旧缩略图不搬”）。
- 旧缩略图/旧 store 均只读；迁移测试用 sha256 证明旧文件不变。

## 4. 错误处理

`MediaErrorDescription` 把底层错误写入 UI：

```text
Scan failed: <localizedDescription>
Error: <domain>(<code>) path=<path> [underlying=<domain>(<code>)]
The index is stored under Application Support; the media folder was not modified. Check Console for details.
```

`os.Logger`（`scan`/`library`）也记录 `root`、store 路径、`domain`、`code`、underlying error 和路径；不再只有 `permission`。`BookmarkStore` 的 `UserDefaults` key、保存/解析逻辑未改。

## 7. 回滚与运维说明

- 旧 `<root>/.mediaviewer` 不自动删除；确认新索引稳定后，用户可手动清理。报告不执行删除。
- 如果新 store 损坏且旧 store 仍在，可删除 Application Support 下对应 `<hash>/Store`，下次启动会重新复制旧 store；旧媒体目录不受影响。
- 缩略图在 exFAT 上重建，首批滚动的首屏延迟由缩略图生成门控保护；旧缩略图不搬运。
- 未修改 `/Volumes/Lexar` 的权限、挂载参数或任何媒体文件。

## 8. 验证限制

- macmini 30–35 s 观察窗口内未触发网格缩略图请求；因此该次新目录只有 store 文件。缩略图路径已在办公 Mac APFS 上验证（134 个按需复制），exFAT 上走重新生成路径。
- 真实 exFAT 的“旧缩略图不搬”通过 `fileSystemType == "apfs"` 分支保证；macmini 上旧 `.mediaviewer` 未被写入。
