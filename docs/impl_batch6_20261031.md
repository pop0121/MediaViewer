# MediaViewer 实现批次6交付报告（2026-10-31）— 方案A：播放内实时画质增强

结论（先看这个）：
- **macmini 上可用的最重链是完整链：CIMedianFilter → CIUnsharpMask。**
  v04（1220×720@30fps）30s 实测 **29.93fps、掉帧 0.24%、处理 p95 19.75ms**；
  v05（1280×720@25fps）实测 **24.97fps、掉帧 0.14%、处理 p95 19.39ms**。
  两项均满足 `≥24fps 且掉帧 <5%`，因此没有启用降级链。
- 降级链也在 macmini 实测：只 sharpen 和只 median 均达标，但完整链已经达标，最终产品使用完整链。
- 处理在**源分辨率**进行（`renderScale = 1.0`），放大仍交给 AVPlayerLayer；播放链路未引入 320/1024 缩略图层。
- 增强开关**默认关**，状态存 `UserDefaults("videoEnhancementEnabled")`；全屏视频右上角显示 “Enhance”。开关关闭时走批次5的原生 `AVPlayerItem` 路径，不挂 custom compositor。
- 开关切换通过给同一个 `AVPlayerItem` 赋/清 `videoComposition`；macOS 会因此在内部把播放头回到 0，本实现先记录 `currentTime`/`rate`，赋完立即 seek 回去并恢复播放。实测播放头从 `0.62s → 0.67s`、`1.95s → 1.95s`，rate 始终 1.0，不重建 item。
- 视觉对比已落盘：`/private/tmp/mvbench/enhance_compare/v05-t120-off.png` 与 `v05-t120-on.png`（办公 Mac 与 macmini 同名路径）；块状边缘/蚊式噪声有可见减少，文字和虚线边缘更紧，极亮边缘有低强度锐化晕，未出现新的明显 macroblock。

测量环境：
- 办公 Mac：Darwin 23.6.0 x86_64，Xcode 15.4，Swift 5.10。
- macmini：Intel i5-8259U + Iris Plus 655，macOS 14.7，x86_64，Metal 3。
- 测试样片：`/tmp/mvbench/lib3k_clone/media/v04.mp4`（1220×720、30fps、322s）、`v05.mp4`（1280×720、25fps、900s）。只读。

## 1. 实现

### 1.1 自定义 AVVideoCompositor

新增 `Sources/MediaViewer/Services/VideoEnhancementCompositor.swift`：

- `VideoEnhancementCompositor: NSObject, AVVideoCompositing`
  - `sourcePixelBufferAttributes` / `requiredPixelBufferAttributesForRenderContext` 均为 BGRA。
  - 串行渲染队列 + `CIContext(mtlDevice:)`；使用 `renderContext.newPixelBuffer()` 获取输出，`CIContext.render(_:to:bounds:colorSpace:)` 输出。
  - 通过 `request.sourceFrame(byTrackID:)` 取源帧；按当前 instruction 的 layer transform 处理源方向；90°/270° 旋转时补偿 Core Image/AVFoundation 顶左/底左坐标差异（v01 等竖屏视频验证正向）。
  - `renderScale = 1.0`，`renderSize` 来自 `AVMutableVideoComposition(propertiesOf:)`（源尺寸/方向变换后的尺寸），不主动放大。
  - 处理链：`CIMedianFilter` → `CIUnsharpMask`（radius 1.2，intensity 0.35，参数在 `VideoEnhancementSettings` 中可调）。
- 降级链由 `VideoEnhancementChain` 控制：`.full`（median+sharpen）、`.sharpen`（只 unsharp）、`.median`（只 median）；`.off` 不挂 compositor。
- 运行诊断 `VideoEnhancementDiagnostics` 记录每帧处理耗时、帧数、p95/max，供 harness 读取；不是散落的 print。

### 1.2 滤镜可用性与替代

在 macOS 14.5 SDK/运行时用 `CIFilter(name:)` 探测：
- `CIMedianFilter`：存在；但属性只有 `inputImage`，**没有 inputRadius**，实际固定 3×3 邻域（等价于 radius 1 的像素邻域），不能按任务文字设置 inputRadius=1。
- `CIVisionDetailSharpen`：**不存在**。
- `CIHighPass`：**不存在**。
- `CIUnsharpMask`：存在，属性 `inputRadius` / `inputIntensity`。

因此 fallback 采用 `CIUnsharpMask`：它本身就是“原图 + 高频（unsharp 高频分量）”的内置实现，等价于高通后叠加；没有额外实现一个质量/性能更差的 `CIHighPass`。参数低强度 1.2/0.35，避免过锐化。若未来系统版本提供 `CIVisionDetailSharpen`，可在同一 chain 内替换，不影响 compositor/界面。

### 1.3 全屏查看器开关

- `FullscreenViewerView` 新增 `@AppStorage("videoEnhancementEnabled") private var videoEnhancementEnabled = false`。
- 视频右上角显示 `Enhance` / `Enhance On` 胶囊按钮；照片不显示。按钮不抢占 Space/方向键逻辑。
- `VideoPlayerView` 新增 `enhancementEnabled: Bool`：
  - 切换开：给当前 item 设置 `videoComposition`（完整链）。
  - 切换关：`item.videoComposition = nil`，回到批次5路径。
  - 不重建 `AVPlayerItem`；保留当前播放头/播放状态。

### 1.4 开关切换的播放头处理

实测给已播放中的 item 赋 `videoComposition` 会让 `currentTime` 回到约 0（切换 on 后 0.56s → 0.04s）。修复路径：

1. 切换前读取 `player.currentTime()` 与 `player.rate`。
2. 赋/清 `videoComposition`。
3. 若原时间 >0，`player.seek(to: time, toleranceBefore: .zero, toleranceAfter: .zero)`。
4. 若原来在播放，恢复 `play()`。

SwiftUI 集成测试（`VideoPlayerView` + NSHostingView）：

| 事件 | item | rate | currentTime | videoComposition |
|---|---|---:|---:|---|
| 开始 | v05.mp4 | 1.0 | 0.62s | off |
| 切到 on | v05.mp4 | 1.0 | **0.67s** | on |
| 切到 off 前 | v05.mp4 | 1.0 | 1.95s | on |
| 切到 off 后 | v05.mp4 | 1.0 | **1.95s** | off |

结论：不是重启 item，切换是一次短 seek；仍可能有一帧左右的画面停顿，但没有回到开头，也没有暂停。

## 2. 帧率与处理耗时（macmini，30s/档）

口径：
- `expectedFrames = 实测墙钟秒数 × 源 nominalFPS`。
- `observedFrames`：60Hz 主线程轮询 `AVPlayerItemVideoOutput.hasNewPixelBuffer` 并取帧的计数。
- `droppedFrames = max(0, expectedFrames − observedFrames)`；`dropped% = dropped / expected`。
- `p95/mean/max`：compositor 自身 `startRequest` 到 `finish` 的处理耗时，含 CI 链 + 输出 pixel buffer；off 没有 custom compositor，p95=0。
- 达标线：**≥24fps 且 dropped <5%**。

### 2.1 macmini 最终数据

| 视频 | 模式 | 处理链 | observed / expected | fps | 掉帧数 | 掉帧% | 处理 mean | p95 | max | 结果 |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|---|
| v04 | off | 无 | 894 / 900.01 | 29.800 | 6.01 | 0.668% | 0 | 0 | 0 | 基线 |
| v04 | **full（最终）** | median+sharpen | **898 / 900.14** | **29.929** | **2.14** | **0.238%** | 9.44ms | **19.75ms** | 31.02ms | **通过** |
| v04 | 降级 | sharpen | 894 / 900.01 | 29.800 | 6.01 | 0.668% | 8.38ms | 13.06ms | 104.79ms | 通过 |
| v04 | 降级 | median | 891 / 900.04 | 29.699 | 9.04 | 1.004% | 7.02ms | 10.75ms | 84.56ms | 通过 |
| v05 | off | 无 | 742 / 750.06 | 24.731 | 8.06 | 1.075% | 0 | 0 | 0 | 基线 |
| v05 | **full（最终）** | median+sharpen | **749 / 750.02** | **24.966** | **1.02** | **0.136%** | 9.20ms | **19.39ms** | 33.51ms | **通过** |
| v05 | 降级 | sharpen | 743 / 750.07 | 24.765 | 7.07 | 0.942% | 7.61ms | 13.15ms | 24.03ms | 通过 |
| v05 | 降级 | median | 743 / 750.06 | 24.765 | 7.06 | 0.941% | 6.50ms | 10.30ms | 20.45ms | 通过 |

说明：
- 最终 full 的 v04/v05 是在最终代码（含方向修正）上的复跑；p95 比初测（16.46/15.51ms）高到 19.75/19.39ms，但仍只有 30fps/25fps 帧预算的约 59%/48%，且 fps/掉帧达标。
- `max` 包含首帧 Metal/Core Image 初始化或偶发调度尖峰；p95 才是稳定帧成本。v04 sharpen 的 104.79ms、v04 full 的 31.02ms 只影响极少数帧，未形成掉帧超标。
- off 的 v05 baseline 掉帧 1.075%，full 0.136%，增强没有让帧率变差；在测量噪声内反而更稳。

### 2.3 最终链

**最终可用最重链：`.full`（CIMedianFilter + CIUnsharpMask）。** 不启用 `.sharpen`/`.median` 降级；降级链保留在枚举中供后续低端机/4K 策略使用。

## 6. 未尽项

1. `CIVisionDetailSharpen` / `CIHighPass` 在 macOS 14.5 不存在；使用 `CIUnsharpMask` 作为内置高通式替代，无法完全复刻任务原文的 Vision detail sharpen 参数。
2. `CIMedianFilter` 没有 `inputRadius` 属性，固定 3×3 邻域；任务中的 “inputRadius 1” 只能按 3×3 近似解释。
3. 方向处理对 90°/270° 的补偿已验证 v01；180°、镜像 transform 和可变 `preferredTransform` 未单独做样本断言。
4. 开关切换需要 seek 以对抗 AVFoundation 赋 composition 后归零；会有约一帧的切换停顿，不是完全无感。未做逐帧切换打断测量。
5. 视觉对比固定 t=120 的文字帧，不能覆盖高运动/复杂纹理；建议后续加自然场景帧和 SSIM/分块噪声指标。
6. macmini 测量为单次 30s，未做热稳定/长时间（5–10 分钟）降频测试；v05 full 的 24.97fps 距 24fps 线只有约 1fps 余量，长时间播放或 4K 源需要重新测。
7. 未用 Instruments 采集 Metal/CI 的 GPU 时间；p95 是 CPU 侧 wall time，p95/max 含少量调度噪声。
