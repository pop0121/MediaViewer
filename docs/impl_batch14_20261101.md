## 2. 实现

### 2.1 目录指纹库

新增 `Sources/MediaViewer/Services/DirectoryFingerprint.swift`：

- 每个目录保存 `(relativePath, dir mtime, entryCount, subdirectoryCount)`。
- 存放在新 store 旁的 `Application Support/MediaViewer/<root-hash>/Store/DirectoryFingerprints.json`，不写用户媒体根目录。
- `DirectoryFingerprintSnapshot` 同时保存 `version`、`lastFullScan`、`dateMigrationVersion`。
- 指纹格式版本 `1`；当前日期迁移版本 `13`。
- 使用 `readdir` 的 `d_type` 区分目录/文件，仅对目录执行 `stat` 读取 mtime；**未变目录不逐文件 stat**。

### 2.2 增量决策

`MediaScanner` 启动流程：

1. 读取已有索引（一次 fetch，用于复用和删除判定）。
2. 目录 walk 出当前指纹，与旧指纹比较：
   - 未变目录：加入 trusted set，直接复用索引路径，不读取文件；
   - 变化/新增目录：只枚举该目录直接子文件并 stat 这些文件；
   - 消失目录：其中的旧路径不进入 discovered，最终删除。
3. 只对 changed files 做 mtime/size diff 和 metadata 提取。
4. 保存索引成功后写入新指纹快照；取消/失败不覆盖旧快照。

### 2.3 全量兜底

以下任一条件走原全量流程（逐文件枚举、diff、提取）：

- 指纹文件缺失 / JSON 解码失败；
- 指纹 `version` 与当前不一致（升级后首启全量一次）；
- 距 `lastFullScan` ≥ 7 天；
- 用户在工具栏点 **Full Rescan**；
- 任一已有行 `dateSourceRaw == nil`（日期迁移未完成）。

`dateMigrationVersion=13` 在成功后写入；之后即使 `derivedDate` 为 nil（Unknown Date），也因 sentinel `unknown` 不再触发重提取。

### 2.4 UI

- 扫描时显示：`Comparing X/Y folders, skipped N…`；索引阶段沿用文件进度；Cancel 按钮沿用批次 1。
- 扫描结束的增量提示：`Skipped N/M unchanged folders. In-place file edits that keep folder mtime unchanged need Full Rescan.`
- 工具栏新增 Full Rescan 按钮（`arrow.triangle.2.circlepath`）；普通刷新按钮仍为增量扫描。
- 报告和 UI 均明确：只改文件内容、不改名/增删时目录 mtime 不变，需等 7 天兜底或手动 Full Rescan。

## 7. 已知局限

- 目录 mtime 不随“只改文件内容、不改名/不增删”变化；这种变更在增量路径不会被发现，需 7 天兜底或手动 Full Rescan。UI 和本报告均提示。
- 目录 mtime 精度依赖文件系统；同时记录 entry/subdir 计数，降低粗时间戳漏检。
- 首次升级/删除指纹/超过 7 天的首启仍要全量；这是设计兜底，不是热启动路径。
- 测试目录新增/删除文件在验收后已清理；用户媒体目录未写。
- 批次 9 外部滚动探针未入库，本批未重新执行；网格/滚动代码未改。
