# MediaViewer 代码审查与性能基线报告

日期：2026-10-31
版本：`45fd16e`（initial commit），Swift 5.10 / Xcode 15.4，macOS 14.6
范围：只读审查 + 性能实测。未修改仓库内任何源码；本文件是唯一新增文件。

---

## 1. 结论（先行）

1. **首屏时间由"扫描 → 全量缩略图 → 反向地理编码"串行决定，且全部完成后才取第一页数据。** 3,007 个文件、空缓存冷启动实测 **88.6s / 98.2s / 91.0s**（三次），其中缩略图生成 **82.3s**。苹果照片在同类库上是"先出网格、缩略图渐进填充"。
2. **滚动卡顿的根因是 960px 缩略图在绘制时于主线程惰性解码。** 单张解码 **7.6ms**，一屏 30 张 **257ms**；自动滚动 12s 实测 **119 次 >25ms 停顿、90 次 >50ms、23 次 >100ms，最大 156.8ms**；同一窗口静止 8s 为 **0 次**停顿。
3. **缩略图规格与缓存严重失配。** 统一 960px、平均 **147KB/张**、解码后 **1.9–2.3MB/张**；而网格单元只有 60–160pt。200MB 的 `NSCache` 实际只能容纳约 **87 张**，3,000 张库里滚动必然反复读盘。
4. **日期分组每次重排创建 N 个 `DateFormatter`。** 3,007 条重排 **193–246ms**（主线程），其中格式化占 **207–228ms/3000 条**，共享 formatter 只需 **6.0–7.3ms**（约 30 倍差距）。缩放滑杆每 0.1 步都会触发一次完整重排 + 网格 relayout。
5. **全屏查看器按原图全尺寸解码。** 5,760×3,840 样张：加载 6ms、**解码 502.7ms**、位图 **84MB**、进程 RSS 从 140MB 涨到 **318MB**；没有相邻预取、没有过渡动画。
6. 另有确定性 bug：视频之间切换会**继续播放上一段视频**（`VideoPlayerView.updateNSView` 不替换 `AVPlayerItem`；代码层面确定，未做 UI 复现）；`ScanResult.removed` 统计公式错误（实测打印 "removed 6014"，实际删除 0）；根目录经符号链接时相对路径计算失效，缩略图静默不生成。

**总体判断：** 当前实现的瓶颈不是 Core Data，也不是元数据提取（照片 0.58ms/张、视频 3.15ms/条、枚举 3,007 文件 37ms），而是 **缩略图层与首屏编排**。按第 6 节 P0 项改造，首屏可从约 90s 降到 1–2s，滚动停顿可降到接近静止水平，且不需要引入第三方依赖。

## 2. 测量口径与方法

### 2.1 环境

| 项 | 值 |
|---|---|
| 机器 | Intel Core i7-8750H，6 核 12 线程，16GB RAM |
| 系统 | macOS 14.6（Darwin 23.6），内建 APFS SSD，磁盘占用 93% |
| 工具链 | Swift 5.10 / Xcode 15.4，`swift build -c release`（`-O`） |
| 源码 | `45fd16e`，审查期间 `git status` 干净 |

### 2.2 样本

- **3,007 个文件 / 1.1GB**：3,000 张照片（以 APFS clone 复制的独立文件，内容取自 `~/Pictures` 的 70 张真实照片，单张 0.08–4.5MB，最大 5,760×3,840）+ 7 个真实 MP4（`~/Movies`、`~/Downloads`）。
- 其中 1 个 MP4（`v03.mp4`）AVFoundation 无法打开（"Cannot Open"），作为失败分支记录。
- 70 张唯一照片中有 **4 个唯一 GPS 坐标**（上海附近）；无 HEIC、无 Live Photo。
- 所有媒体文件只读，仅在 `/private/tmp/mvbench` 下创建 clone/hardlink 与 `.mediaviewer` 输出；未修改 `~/Pictures`。

### 2.3 方法

| 测量 | 工具/口径 |
|---|---|
| 冷启动到首屏 | 用**生产代码构建的 app 副本**，仅注入 `MV_ROOT` 环境变量入口与计时日志（UI/渲染/扫描代码不变）；空 `.mediaviewer`，记录 `setRootURL → 首批 1,000 条 items` 的时间 |
| 扫描/索引 | 用 `swiftc -O` 直接编译生产源文件（`MediaScanner`、`PersistenceController`、`ThumbnailGenerator` 等）成独立 harness，调用真实 `MediaScanner.scan` |
| 缩略图/解码 | 生产 `ThumbnailGenerator`；解码成本用 `CGContext.draw` 强制光栅化后计时（等价于首帧绘制时的惰性解码） |
| 分组 | 调用真实 `LibraryViewModel.toggleCollapsed`（内部走 `Self.group`），3,007 条，取 3 次中位数 |
| 滚动停顿 | app 副本内 60Hz 主线程心跳，间隔 >25ms 记为停顿；自动滚动 320pt/120ms；静止 8s 作对照 |
| 内存 | `task_info(MACH_TASK_BASIC_INFO)` RSS |

**口径说明**
- 所有时间单位为秒(s)/毫秒(ms)，内存为 MB，均为**墙钟时间**，release `-O`。
- 冷 = 删除根目录下 `.mediaviewer`；热 = 索引与缩略图均已存在。
- 样本是 clone 的独立文件，但内容只有 70 张唯一照片；缩略图 CPU 成本与真实 3,000 张不同内容的库同量级（解码按像素计算），**I/O 与页面缓存表现会偏乐观**。
- 3,000 张照片均为 JPEG；HEIC 未覆盖（当前代码也不支持）。

## 4. 架构速览（阶段 0）

- 入口 `MediaViewerApp` → `GalleryView`（唯一窗口）→ `LibraryViewModel`（`@MainActor`）。
- 根目录用 security-scoped bookmark 存 `UserDefaults`；索引与缩略图写在 `<root>/.mediaviewer/{Store,Thumbnails}`。
- 冷/热启动路径**同一条**：`PersistenceController` → `MediaScanner.scan`（全量枚举 + 变更集元数据）→ 地理编码 → 缩略图孤儿清理 → `fetchItems`（1,000 条/批）。
- `MediaScanner` 并发提取元数据（8 并发，按 8 个一批等待），单次 save 应用增删；随后对全部变更文件生成缩略图。
- 网格：`ScrollView + LazyVGrid(adaptive) + Section`；每格 `MediaCellView` 用 `.task` 取缩略图。
- 分组：Combine 监听 `$items`、`$groupingMode`、`$effectiveZoomLevel`，每次全量重建 `[MediaGroup]`。
- 全屏：overlay 上的 `FullscreenViewerView`，本地 `NSEvent` 键盘监听；视频用 `AVPlayerView`。

## 7. 与苹果照片 App 的逐项差距

| 维度 | 苹果照片 | 当前实现 | 差距/证据 |
|---|---|---|---|
| **即时滚动** | 预解码、按显示尺寸的缩略图，滚动不掉帧 | 960px 缩略图在绘制时主线程解码 | 12s 滚动 119 次 >25ms 停顿，最大 157ms |
| **渐进式缩略图** | 先模糊/低清占位，再替换高清 | 首屏前一次性生成全部；网格出现即已是最终图 | 冷启动 90s 内无网格 |
| **预取** | 按滚动方向预取前后若干屏 | 无任何预取；离屏即销毁 `@State` | 回滚需重新读盘（缓存仅 ~87 张） |
| **日期分组交互** | 吸顶头、年/月/日/全部层级、侧边滚动条、捏合切换粒度 | 分段控件 + 滑杆；标题 `yyyy-MM`；头不吸顶 | 每次重排 193–246ms；无层级导航 |
| **缩放自适应** | 捏合连续缩放，单元尺寸动画，缩略图按级替换 | 0.1 步进滑杆 + 150ms debounce + 全量重排/relayout | 拖动即卡；无手势 |
| **全屏查看过渡** | 从缩略图放大、交互式下滑关闭、相邻预载 | 未动画的 opacity overlay；原图全尺寸解码 | 解码 503ms / 84MB |
| **视频播放** | 内联自动播放、声波/进度预览、无缝衔接 | `AVPlayerView` 内联控制；切视频播旧片；无预载 | 确定性 bug + 无过渡 |

补充差距（不在本次目标内，但影响"像照片"的感知）：无相簿/收藏/搜索、无人物/场景、无 iCloud、无 Live Photo、无编辑。

## 8. 未测项与限制

1. **未导出 Instruments "Animation Hitches" trace**。滚动数据来自 app 内 60Hz 主线程心跳（同一机制的轻量替代），能测到主线程停顿，但不能给出系统级 hitch 分类。
2. **视频播放流畅度未做帧率测量**（需要屏幕录制/HUD 权限），仅代码审查；`v03.mp4` 无法解码，视频样本覆盖有限。
3. **未与 Photos.app 做同库 A/B 计时**（Photos 需要导入其图库，且自动化受限）。
4. **app 冷启动 90s 与无 UI 进程 37s 的差异未完全归因**。两者代码相同；app 内已确认缩略图任务确实以最多 8 并发、非主线程执行（300 文件样本：3.44s，active 峰值 8，`main=false`）。差异可能来自持续 90s 负载下的热降频、I/O 竞争与 App Nap/QoS，需在实现阶段用 signpost 复核。
5. 样本为 clone 文件，内容重复 70 份，**I/O 与页面缓存偏乐观**；真实 3,000 张不同照片的冷启动只会更慢。

## 9. 复现方式

性能 harness 位于 `/private/tmp/mvbench`（未加入仓库）：

```
probe     # 单文件元数据/缩略图/解码/变体对比
bench     # 生产 MediaScanner.scan + 生产分组路径（3k 库）
bench3    # 启动流水线分阶段计时 + 一屏 30 张解码
appcopy   # 生产 app 副本，仅注入 MV_ROOT / MV_SCROLL_BENCH 计时
```

```bash
# 构建
swift build -c release

# 单文件成本（样本库为 70 张真实照片 + 7 段视频的 hardlink 副本）
/tmp/mvbench/probe /private/tmp/mvbench/lib cold
/tmp/mvbench/probe /private/tmp/mvbench/lib warm

# 扫描/分组基线（3,007 文件）
/tmp/mvbench/bench /private/tmp/mvbench/lib3k_clone cold

# app 内滚动停顿（需先用 appcopy 构建 MV.app）
MV_ROOT=/private/tmp/mvbench/lib3k MV_SCROLL_BENCH=1 MV_SCROLL_SECONDS=12 \
  /tmp/mvbench/MV.app/Contents/MacOS/MediaViewer
```
