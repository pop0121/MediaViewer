# MediaViewer 批次11交付报告（2026-11-01）— 年/月/日分组折叠修复

## 结论（先行）

**折叠 bug 的根因在 UI 命中层：吸顶分组标题里的 `NSTextField` 文字标签吞掉了点击，`GridPinnedHeaderView.mouseDown` 根本没有被调用；同时画布只在吸顶位置有一个真实 header，内容区没有可点击的组标题。** 这不是 ViewModel 折叠状态写错，也不是 section 高度缓存把 `isCollapsed` 覆写回去。

- 修复后，标题文字区域点击可命中 `GridPinnedHeaderView` 并触发 `toggleCollapsed`；日志链路完整：`pinned header mouseDown` → `toggle` → `regroup` → `apply geometryChanged collapsed=[...]`。
- 内容区新增真实 CALayer 分组标题（可点击），不再只能点窗口顶部的吸顶标题；折叠组只保留 30 pt header。
- 修复了折叠时列宽从 900 变为 885（滚动条出现）导致全列重排、文档高度反而增加的跳变；折叠前后列数稳定。
- 复现矩阵 **9 项全部通过**；本机 `swift test` **13/13**；macmini 矩阵 **10/10**；双机 `swift build -c release` 通过。
- 本机 12 s 常规滚动：稳定重复组 **>25 ms 5–9 次、>50 ms 0–1 次、max 42.6–64.4 ms**；折叠态 **>25 ms 5–10 次、>50 ms 0–1 次、max 33.1–54.0 ms**；RSS **123–136 MB**。
- macmini 本样本（索引 3,007 条，但首屏 1,000 条在本机库中只形成 1 个 section）滚动有 0–6 次 >25 ms、0–3 次 >50 ms、max 47.8–94.1 ms 的波动；属该样本单 section 大量图块解码的噪声，未作为折叠路径的通过依据，详见第 6 节口径。

### 1.1 失败证据（修复前）

修复前的焦点测试直接命中到了标签而不是 header：

```text
XCTAssertTrue failed - header receives hit test,
got Optional(<NSTextField: 0x...>)
```

这说明点击标题文字时事件进入 `NSTextField`，`GridPinnedHeaderView.mouseDown` 不会被调用；因此 `LibraryViewModel.toggleCollapsed` 也不会执行。用户看到的“点了没反应/立刻弹回”首先是这一层断掉。

修复后测试断言：

```text
PASS: header itself, not NSTextField, receives title click
Log: pinned header mouseDown title=2022
Log: toggle mode=years id=2022 wasCollapsed=false nowCollapsed=true
Log: regroup count=3 collapsed=2022
Log: apply geometryChanged force=false collapsed=[2022] groups=3
```

### 1.2 修复前的高度跳变（第二层原因）

画布原先用 `scrollView.contentView.bounds.width` 计算列数。窗口出现传统滚动条后，内容宽度从 900 变成 885：

```text
before: contentH=10240 width=900
after:  contentH=11993 width=885   ← 折叠后反而增高 1753 pt
```

改为用稳定的 `scrollView.bounds.width`（900）布局后：

```text
before: contentH=10240 width=900
after:  contentH=10151 width=900   ← 仅减少被折叠组的 119 → 30
```

所以“折叠后跳一下/弹回”不是高度缓存把 collapsed 改回去，而是列数变化导致全量 section 重排。折叠标志本身在 `GridCanvasLayout` 中直接参与 `sectionHeight` 计算，`GridContainerView.apply` 的 signature 也包含 `isCollapsed`；矩阵中的高度/恢复断言均通过。

## 2. 改动

### 2.1 `Sources/MediaViewer/Views/GridCollectionView.swift`

- `GridPinnedHeaderView.hitTest(_:)` 返回自身：标题/数量标签不再吞点击。
- 新增 `GridSectionHeaderLayer`：内容区每个可见 section 一个真实 CALayer header，显示标题、折叠计数和 chevron；由图层池复用。
- `GridCanvasLayout.header(at:)`：header 几何命中。
- `GridCanvasView.mouseDown`：先判 header，再判图块；内容区组标题可直接折叠/展开。
- `updateHeaders(sections:)` 与 `lastHeaderSections`：折叠组没有图块时也会维护 header，不依赖 `lastVisibleKeys` 是否变化。
- 布局宽度使用 `scrollView.bounds.width`，避免传统滚动条出现时 900→885 的列数跳变。
- `scrollerStyle = .overlay`，固定滚动条行为。
- `Log.collapse` 仅记录关键链路（点击、toggle、regroup、geometryChanged），不使用散落 `print`。

### 2.2 `Sources/MediaViewer/Services/LibraryViewModel.swift`

- `toggleCollapsed` 前后记录 mode、group id、was/now collapsed、regroup 后的折叠集合；逻辑本身未改（原逻辑已正确保存到 `collapsedGroupIDsByMode` 并重新分组）。
- 修复后数据层矩阵确认：切分段、改密度、Places 往返、连点均保留/恢复正确。

### 2.3 `Sources/MediaViewer/Services/Log.swift`

- 新增 `Log.collapse` logger。

## 6. 风险与边界

1. **吸顶标题与内容区标题并存**：内容区 header 是真实 CALayer，吸顶 header 仍是独立 `NSView`；点击顶部时由吸顶 header 处理，点击内容区标题由画布处理。两者都调用同一个 `onToggle`。
2. **宽度口径**：布局固定用 `scrollView.bounds.width`；传统滚动条会覆盖文档最右侧约 15 pt，但不会改变列数/高度。若后续要求滚动条完全不覆盖内容，需要自定义 overlay scroller。
3. **macmini 样本不一致**：其 Store 当前首屏单 section，不能直接和办公机 15 个 section 的滚动数字横向比较；报告中保留原始轮次，不包装成通过。
4. **“全部折叠”按钮不存在**：矩阵第 8 项按“逐组展开恢复全部”验证；没有新增工具栏按钮。
5. **性能尖峰**：常规滚动仍观察到偶发机器调度尖峰（例如 206.5 ms/一次）；折叠态 5 轮均低于 60 ms。
