# MediaViewer 批次7交付报告（2026-10-31）— Enhance 竖版必错 / 横版偶发

## 结论（先行）

根因是**实际播放路径下取不到 layer transform**，不是 CI 链本身：

- 批次6的 `transform(for:)` 只接受 `AVMutableVideoCompositionInstruction`。`AVAssetImageGenerator` 走的是可变 instruction，能 cast；真实 `AVPlayer` 播放给自定义 compositor 的是**不可变 `AVVideoCompositionInstruction`**，cast 返回 nil。
- transform 为 nil 后，源帧保持 568×320（或 640×360），但 `context.size` 已经是竖屏 320×568/360×640；再按 renderSize 裁剪，只剩源图的一半区域。对 v01，前置帧内容包围盒 320×320（y=248），后置恢复 320×568；m_r90 前置 360×320（y=280），后置 360×590。这就是“只渲染一半画面”。
- 同时没有应用 90°/270°/180°/镜像 transform，内容方向错误；before 的方向分类 best=rot90/rot270/flop90/flop270（见下表），这就是“画面颠倒/转错”。
- 横版偶发：纯 identity 的横版源不应失败；带 180°/镜像/旋转 preferredTransform 的横版源在 cast nil 时失败，所以表现为“偶发”。矩阵中 m_r180_normal before RMSE 0.132、m_r0_mirror 0.106，after 0.043/identity。
- 修复：cast 改成公共 `AVVideoCompositionInstruction`；补 transform ramp 插值；并用压力日志中发现的问题把 `startRequest` 的 compositor 生命周期从 weak 改为强持有，避免 request 未 finish 就被释放（macmini 老压力日志出现过 6 次 “unfinished AVAsynchronousVideoCompositionRequest deallocated”）。

修复后：12 变体矩阵 + v01 的 full/toggle 全部 identity 通过；本地/ macmini 3 分钟 ×3 轮压力黑帧 0、不一致 0、无崩溃、无 unfinished request 警告；性能未回归。

## 1. 根因判定（逐项）

### 1.1 preferredTransform / instruction 类型：确认，主因

证据：

- 批次6日志（真实 player）：`MV_COMPOSITOR context=(360,640) source=640x360 transform=nil ... croppedExtent=(0,0,360,360)`；v01：context 320×568，source 568×320，transform nil，cropped 320×320。
- cast 后同一真实 player：v01 transform `a=0 b=1 c=-1 d=0 tx=320 ty=0`，transformed extent 320×568；m_r90 `a=0 b=-1 c=1 d=0 tx=0 ty=640`，transformed extent 360×640。
- image generator 路径能 cast mutable，所以批次6生成截图和 bench 没有暴露；真实 player 才暴露。

结论：必错类。

### 1.2 BGRA source attributes 与解码器格式：推翻

- 矩阵全部 H.264 yuv420p 源；另生成 HEVC yuv420p 竖版物理变体，真实 player full RMSE 0.04259、方向 identity；sourcePixelBufferAttributes 统一 BGRA，没有因格式不同出现黑帧/错位。
- 压力中也没有格式相关失败；见第 3 节。结论：不是本 bug 主因。

### 1.3 newPixelBuffer/CIContext 与 seek/toggle 并发：部分确认（request 生命周期），已修

- 第一轮 macmini 压力日志出现 6 次 `unfinished AVAsynchronousVideoCompositionRequest deallocated`。
- 原 `startRequest` 用 `queue.async { [weak self] ... }`，compositor 在 request 排队期间可能释放，request 永远不会 finish；这会造成偶发闪帧/黑帧风险。
- 改为强持有 self 直到 process 完成；最终压力无该警告。newPixelBuffer 由 renderContext 分配、每 request 独立，没有自行复用。
- 结论：不是竖版必错的主因，但确认并修复了一个偶发风险。

### 1.4 renderSize / bounds 用了变换前尺寸：确认是主因的表现，不是独立 bug

- cast 后 renderSize 与 transform 后 extent 完全一致（见 2.1）；cast nil 时 renderSize 是竖屏、extent 仍是横屏，裁剪才会半帧。
- 没有发现 track matrix 含非正交/平移分量导致 bounds 计算错；标准 90/180/270/镜像矩阵均通过。
- 结论：修复 instruction 后消失；不再单独改 renderSize。

### 1.5 CI 色彩空间：推翻为方向 bug 原因

- 源/输出 BGRA，enhance 前后颜色差异来自 median/sharpen，不是方向；矩阵 full/toggle 都 identity 通过。保持现有 DeviceRGB；未观察到颜色错位。结论：不是本 bug 主因。

## 5. 修复内容

`Sources/MediaViewer/Services/VideoEnhancementCompositor.swift`：

1. `AVMutableVideoCompositionInstruction` → `AVVideoCompositionInstruction`（根因；真实 player 的不可变 instruction）。
2. `getTransformRamp` 的 start/end 按 compositionTime 做线性插值（支持非静态 transform；静态路径仍取 start）。
3. `startRequest` 从 `[weak self]` 改为强持有 self 直到 request finish；修复 queued request 在 compositor 释放后未 finish 的警告/潜在闪帧。
4. 保留现有 90/270 的 top-left/bottom-left 中心翻转补偿；矩阵全过，没有改动方向数值。

## 7. 未尽项 / 未复现

1. 横版偶发只在带 transform 的样本上稳定复现（m_r180/m_r0_mirror 等）；纯 identity 横版不复现，符合“偶发”取决于文件是否带旋转/镜像元数据。
2. 压力只覆盖 v04/v05 两段 H.264，未覆盖 4K/HDR/10-bit/可变帧率/非线性 transform；HEVC 竖版单测通过。
3. 竞态只以压力 + unfinished 警告为观测，没有 Instruments 级别的逐 request 追踪；最终 3 轮无警告/无黑帧。
4. 开关切换仍是“记录时间→赋/清 composition→seek 回去”，有一次短 seek；不是完全无感。
5. 黑帧检测是密集抽帧（10Hz，8px 网格 max<5），不是逐帧 GPU 检测；压力中的 noFrameSamples 是轮询窗口内无新帧，不作为失败。
